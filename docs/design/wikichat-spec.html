Les 5 vues, en pixels.

Chaque vue : un artboard hi-fi à taille réelle (default state) + un ou deux variants critiques (empty, alerte, état chargé). Notes de design en marge. Les sections cross-cutting (routing, layout, motion, loading/error) renvoient au cahier markdown qui détaille les algos.

Bienvenue.

Aucun projet, aucune idée, aucun agent. Capte ta première idée pour démarrer — elle deviendra le germe de ton premier projet.

Notes de design · 01
  • Tonalité : un titre serif italique en majeur (« Bonjour. Trois choses… »). Le nombre est dans le copy, pas dans une stat-card. Pas de chiffres orphelins en gros, jamais.
  • Pas de stats vanity. Chaque ligne montre une chose actionnable (trier, ouvrir, archiver) ou diagnostique (qui a CI rouge ?), rien d'ornemental.
  • Vide ≠ erreur. L'empty state du tout-premier matin est éditorial, accueillant, dirige vers la seule action utile.
  • Hover révèle l'action — ne jamais afficher un bouton "→" par défaut, ça encombre. La rangée est cliquable en entier (toute la zone, pas juste le mot).
  • Cap d'items par tuile : 4. Au-delà, "voir tout (12)" en bas en lien ambré. Pas de scroll dans la tuile.

Notes de design · 02
  • Hiérarchie visuelle : projet (gros, sombre, posé) > idée (petit, papier, flottant) > agent (pin, par-dessus tout). C'est l'inverse du flux : ce qui est contributeur est au-dessus du contenant.

03

Capture

/#capture?proj=archipel

Overlay déclenché par ⌘K en mode capture, ou par le bouton primaire du peek panel. Critère de succès : 5 secondes entre l'envie d'écrire une idée et l'idée enregistrée. Tout le reste (axes, projet, scope) est inféré et corrigible.

default — projet inféré · axes auto
⚡ capter une idée 17h32 · mer 8 mai
@archipel #auth #blocker + ajouter axe ⌘Pchanger projet
esc annuler ⌘⇧↵ capter + ouvrir
Notes de design · 03
  • Projet inféré : si le user vient du peek d'un projet → ce projet. Sinon → projet le plus récemment touché. Toujours visible, toujours ⌘P pour changer.
  • Axes auto : extraits du body via NLP local (matching tags connus + similarité d'embedding). Toujours éditables, toujours commentés (badge ambre = inféré, jamais "magique").
  • Pas de bouton "Annuler" visible — escape, c'est partout. Les 3 actions clavier sont au pied : esc, ⌘↵ (capter), ⌘⇧↵ (capter + ouvrir le projet).
  • Body optionnel. Une idée en 1 ligne titre est une idée valide. Ne jamais forcer le détail.
  • Animation entrée : 180ms, opacity 0→1 + translateY(8px→0) + backdrop-blur 0→10px. Sortie 120ms.

Notes de design · 04
  • 4 décisions, 4 lignes. Pas de wizard multi-étapes, pas d'accordéon. Tout est sur un seul écran.
  • Preview live : la commande shell équivalente est rendue en temps réel. Bénéfice : tu peux la copier, ou apprendre à l'écrire directement.
  • Options avancées derrière ⌘. — modèle, branche, env vars, secrets. 95% du temps, inutile.
  • Empty state (aucun projet) : la modal n'est jamais déclenchable. Le bouton "spawn" du HUD est masqué tant qu'il n'y a pas de projet.

Notes de design · 05
  • Watermark unread : ligne ambre + label « non lus depuis Xm » centré. Persistant en localStorage par conversation. Click sur la ligne = "marquer lu" (la ligne disparaît, scroll-to-bottom).

06

Hash routing

/#<view>[/<id>][?params]

Hash router minimal — pas de framework. Tout est deep-linkable, y compris les overlays et la sélection canvas. Bénéfice : tu peux coller une URL dans #wikichat (le projet) et l'autre dev arrive exactement sur ton écran.

Routes
  • /#today — landing matin (default si rien)
  • /#canvas — canvas plein écran
  • /#canvas?proj=wikichat — canvas + peek panel ouvert sur ce projet
  • /#canvas?proj=wikichat&zoom=1.4&cx=240&cy=180 — canvas + zoom + position pan
  • /#capture — overlay capture (projet inféré)
  • /#capture?proj=archipel — overlay capture pré-scopé
  • /#spawn?proj=wikichat — modal spawn pré-scopé
  • /#chat/wikichat — vue chat, projet présélectionné, premier agent en vol
  • /#chat/wikichat?agent=alice — vue chat, agent ouvert
  • /#chat/wikichat?agent=alice&at=msg-128 — chat scrolled à un message précis
Sémantique
  • Le segment principal (today, canvas, capture, spawn, chat) détermine l'écran de fond.
  • capture et spawn sont des overlays : si on y arrive directement, le fond est canvas par défaut. Esc → retour au fond.
  • Les query params sont des hints, jamais des assertions. Si ?proj=foo et que foo n'existe pas, on ouvre la vue sans le param et on log un warning console.
  • Le router ne re-render pas la vue si seul un query param change (ex: zoom/pan du canvas) — il met à jour l'URL en replaceState debounced 300ms.
Raccourcis globaux
  • g t → /#today · g c → /#canvas · g s → /#chat
  • ⌘K → ouvre cmd palette (sans changer la route, restaure à la fermeture)
  • ⌘N → /#spawn?proj=<current>
  • ⌘↩ → /#capture?proj=<current>
  • esc → ferme overlays · puis désélectionne · puis retour à /#today
07

Layout algorithm

canvas auto-layout

Tranché : grid auto + override draggable persisté. Le layout par défaut est calculé à chaque load. Si l'utilisateur drag un projet, sa position est figée dans localStorage et le layout auto coule autour.

Algorithme par défaut
  • Étape 1 — clustering. Les projets sont groupés par cluster_id (champ explicite, sinon "default"). Chaque cluster a un label éditable et un seed de position (top-left).
  • Étape 2 — packing. À l'intérieur d'un cluster, les projets sont packés en grille auto (colonnes basées sur la largeur du cluster, gap 24px). Tri : pinned d'abord, puis par activité récente desc (dernier commit/idée/spawn).
  • Étape 3 — idées. Chaque idée est posée près de son projet rattaché (offset radial pseudo-aléatoire stable par id, rayon 80–140px). Si pas de projet rattaché, dans la "sandbox" en bas.
  • Étape 4 — agents. Posés au-dessus du projet où ils tournent, en pile horizontale (offset y : -28 par agent supplémentaire).
Override draggable
  • L'utilisateur peut drag un projet, une idée, ou un cluster entier.
  • Position figée dans localStorage[wikichat.layout.<projectId>] = {x, y, fixed: true}.
  • Au prochain load, les overrides sont appliqués après l'auto-layout. Les éléments sans override coulent autour.
  • Bouton ⌘⇧L = "reset layout" — efface tous les overrides.
Pourquoi pas du force-directed ?
  • Force-directed ferait bouger le canvas à chaque ajout d'idée. Insupportable — le user perd son repère spatial. La spatialité est la valeur de cette vue.
  • Grid auto est prévisible : un projet apparu hier est au même endroit aujourd'hui. C'est la mémoire spatiale qui fait la valeur.
08

Motion · transitions de vues

animations

Discipline d'animation : discret, rapide, pas de bling. Les transitions servent à orienter (où je viens, où je vais), pas à impressionner.

Durées par défaut
  • 140ms ease-out · hover, focus, sélection (transformations locales)
  • 180ms ease-out · entrée d'overlay (capture, spawn, cmd palette) — opacity + translateY(-4px) + backdrop-blur 0→10
  • 120ms ease-in · sortie d'overlay (légèrement plus rapide qu'entrée)
  • 200ms ease-out · peek panel slide-in (translateX(20px) + opacity)
  • 220ms cubic-bezier(.2,.7,.2,1) · transitions entre vues (today ↔ canvas ↔ chat) — crossfade + scale .98→1
  • 320ms cubic-bezier(.6,-.2,.2,1.4) · entrée d'une nouvelle idée (overshoot léger pour faire « papier qui tombe »)
  • 2000ms infinite · pulse "live" sur agent — opacity 1→.55→1
Règles dures
  • Aucune animation > 400ms, sauf pulse. Au-delà = perçu comme "ça lague".
  • Pas d'animation au load initial. Les éléments apparaissent en place — pas de stagger fade-in.
  • respect prefers-reduced-motion : toutes les animations passent à 60ms ou sont désactivées.
  • Le canvas zoom n'est jamais animé — c'est un transform direct. L'animer le rend mou.
09

Loading · Error

états transverses

Loading et error sont locaux, jamais en pleine page. Une vue charge ses régions séparément ; un échec n'invalide pas l'écran.

Loading
  • Skeleton sur les régions qui chargent : 2-3 lignes de blocs bg-2 avec une animation shimmer (gradient ambre soft 1500ms linear infinite). Pas de spinner.
  • Délai d'apparition : 200ms. Si la donnée arrive avant, pas de skeleton du tout (évite le flash).
  • Optimistic UI : capture d'une idée affiche la note immédiatement. Si erreur serveur, la note prend un border rouge muted + bouton retry.
  • Connexion live (SSE) : indicateur en HUD top-right — 3 états (connected vert · reconnecting ambre pulse · offline rouge).
Error
  • Inline d'abord. Une carte projet inaccessible affiche un état grisé + dot rouge + tooltip "fetch failed · retry".
  • Toast jamais. Les toasts disparaissent — les erreurs persistent. À la place : pastille HUD top-right qui dit "X erreurs · voir".
  • Page d'erreur globale uniquement si l'auth échoue (impossible de charger quoi que ce soit). Sobre, avec status + retry + lien support.
  • Agent crashed : la pill devient grise, le chat affiche un message système ambre "Agent terminé sans clean exit · code 137 · restart ?".
